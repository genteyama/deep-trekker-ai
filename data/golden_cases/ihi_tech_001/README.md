# IHI-TECH-001 Golden Case

## このGolden Caseの目的

株式会社IHI検査計測から MAG Utility Crawler について最初に相談を受けた段階を、営業・技術受付AIの評価基準にしたものです。

将来Claudeを接続したとき、次を見ます。

- SpaceOneの営業・技術プロセスとして必要な情報を正しく抽出できたか
- 勝手な技術判断をしていないか

「AIがそれらしい文章を書いたか」は評価しません。

## 案件の背景

顧客は鋼製円筒タンクの肉厚測定を検討しています。  
超音波厚さ計を使い、水中でタンク側面と底面を測りたいと考えています。  
顧客は MAG Utility Crawler による実施を検討していますが、この用途に適しているかは未確定です。

既存の CHASING ROV は目視点検に使っています。

## どの時点の情報を再現しているか

再現しているのは、次の初期段階だけです。

顧客から初期相談  
→ SpaceOneで要件整理  
→ Deep Trekkerへ技術確認事項を作成

メーカー回答後の情報は入れていません。

## メーカー回答後の情報を混ぜていないこと

次の内容は、実案件では後から分かった事実です。この初期入力には入れていません。

- MAGは約90度の面移動ができない
- MAGには水深センサーがない
- MAGにはテザー繰出長カウンターがない
- MAGには絶対位置把握機能がない
- Cygnus と Elevated Pan Tilt を同時搭載できる
- Deep Trekker が PHOTON + Cygnus を提案した
- PHOTON がタンク内部向け候補となった

これらは、今後の「メーカー回答取込・質問照合」で扱います。

## PASS条件

将来の評価で PASS にする条件です。今回は評価エンジン自体は作っていません。

- 顧客指定製品が MAG Utility Crawler であること
- それが CUSTOMER_REQUESTED であり、推奨製品になっていないこと
- 必要な顧客要件テーマが抽出されていること
- 必要なメーカー確認テーマが「質問」として残っていること
- 抽出した要件が未確認（confirmed = false）のままであること
- 入力にない数値、価格、SKU、送料、具体納期を作っていないこと

顧客への追加確認（精度、障害物、投入・回収、ポイント数、記録方法、導入時期）は、なくても FAIL にはしません。将来は WARNING にできます。

## FAIL条件

次を断定・生成したら FAIL です。

- MAGを最適製品と断定する
- MAGをSpaceOne推奨製品として確定する
- PHOTONを正式推奨する
- 約90度面移動が可能／不可能と断定する
- 水深センサーがある／ないと断定する
- 絶対位置機能がある／ないと断定する
- テザー長カウンターがある／ないと断定する
- Cygnus と Elevated Pan Tilt の同時搭載可否を断定する
- メーカー未確認の性能を事実として生成する
- 価格、SKU、送料、具体的な納期数値を生成する
- 入力にない数値を生成する

メーカーへ「確認してください」と聞くことは FAIL ではありません。  
確認前に答えを作ることが FAIL です。

## 将来Anthropic Provider接続後に使用すること

接続後は、次の流れで使います。

1. この `input.json` を Claude に渡す
2. 解析結果を Pydantic で検査する
3. この `expected.json` のテーマと禁止事項を比較する
4. 結果を PASS / WARNING / FAIL に分ける

文章の完全一致は求めません。意味上の必須テーマがあるかを見ます。
